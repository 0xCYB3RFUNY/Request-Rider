## 0. Три факти, які встановлено до таблиці

**1. Жоден наш файл не читає клони з диска.** Виміряно:

```
grep -rIn "(arachni|dalfox|cariddi|dirsearch|spidersuite|titus|lonkero|
           creepyCrawler|Hunner|XSSTRON|xsser|jaeles|BlackWidow|...)/"
    engine web | grep -v _reconciliation | grep -v _test
→ порожньо
```

Клони — **виключно референс для звірки**, а не runtime-залежність. Це важливо:
реєстр має сенс лише тому, що звіряти є з чим, і жоден тест не падає, якщо
клон зник.

**2. Прямі Go-залежності — 4 зовнішні інструменти.** `engine/go.mod`:

| пакет | статус у go.mod | що реально використано |
|---|---|---|
| `projectdiscovery/httpx` v1.11.0 | пряма | `osint_http_probe.go` — весь `runner.Result` |
| `projectdiscovery/katana` v1.6.2 | пряма | краулер OSINT-графа |
| `projectdiscovery/nuclei/v3` v3.11.1 | пряма | `pkg/scanner/` — рушій зовнішнім процесом |
| `BishopFox/jsluice` | пряма | `target_javascript.go` — ендпоїнти/змінні/секрети з JS |
| `projectdiscovery/tlsx` v1.3.2 | **`// indirect`** | лише `clients.CertificateResponse` — тип відповіді |
| `projectdiscovery/wappalyzergo` v0.3.0 | **`// indirect`** | **нуль** прямого виклику |

`tlsx` і `wappalyzergo` присутні лише як транзитивні залежності httpx/katana.
«Є в `go.mod`» ≠ «інтегровано» — саме цю помилку робив попередній звіт.

**3. Ліцензійна небезпека знята рішенням власника від 2026-10-08:** клони
лишаються в дереві відкрито, як референс. У `.gitignore` для них не було
жодного патерна — блок, який це описував, був лише коментарем (див.

**Здатностей у клоні:** словникові списки `db/` (за темою), розширення файлів

**Що відкрите:** маски розширень (`-e`), рекурсія, фільтри за статус-кодом,
`--max-time`. Тобто інструмент **не не інтегрований** — інтегровано лише

**Ліцензія:** GPL-2.0. Код **не** переносимо. Використання як зовнішнього

**Що в нас — виміряно точно:**

```

```

Наша знахідка nuclei несе `cve` і `cwe` (`nuclei_exec.go:262-263`) і **більше
нічого**. Модель `ScannerRun` (`web/lab/models.py:272`) зберігає `findings`
як `JSONField` без окремого поля пріоритету.

**Чому це найцінніша знахідка звірки.** `ІНТЕГРАЦІЯ_ІНСТРУМЕНТІВ.md` вже
називав це єдиним найціннішим пунктом ітерації B («знахідка nuclei вже має
`template_id`, з якого видно CVE; якщо `vulnx` дає EPSS, то кожна знахідка
отримує пріоритет»), і зараз **підтверджено виміром**: `template-id` →
CVE → EPSS/KEV/PoC — це рівно один виклик на знахідку, ліцензія MIT.

**Це єдина знахідка, що не дублює вже наявне.** Gf-Patternс дає підказки
оператору, WAF-база — факт про середовище, а EPSS/KEV — **порядок роботи**:
при 200 знахідках оператор сьогодні читає їх у порядку появи, а з EPSS
починає з тієї, яку реально експлуатують.
