**Проєкт:** RequestRider  
**Ситуація:** робоче дерево `/home/kali/Desktop/Request-Rider` не містить `.git`, тому
звіт описує фактично внесений стан файлів, а не `git diff`.

## Коротко

З runtime-контуру застосунку прибрано жорстко задані верхні межі, тихе
обрізання даних, приховані квоти, семафори активних job-записів і
fallback-значення конфігураційних `envLimit`/`env_limit`. Користувацькі
параметри тепер не обмежуються прихованим максимумом застосунку.

Залишено лише параметри, які явно вводить оператор, та протокольні/синтаксичні
перевірки, без яких неможливо сформувати коректний HTTP, URL, workflow або
browser action. Наприклад, `iterations` і `concurrency` досі повинні бути позитивними,
`delay_ms` та timeout не можуть бути від'ємними, а HTTP method має бути
дійсним токеном. Це не приховані верхні квоти.

## 2. Go engine

### `engine/main.go`

Видалено:

- `maxTargetPages` і `maxTargetDepth`; `max_pages <= 0` тепер означає
  необмежену кількість сторінок, `max_depth < 0` — необмежену глибину;
- `maxAnalysisBodyBytes` та `readAnalysisBody` truncation;
- `LimitReader` для JSON Scanner і response body;
- стандартні 15-секундні timeout для OSINT, route check, Target та source-IP
  lookup;
- мінімальну route-check timeout-перевірку;
- два DNS retry і 2-секундний DNS context;
- вісім redirect hops і два retry у OSINT fetch;
- 32/4 default worker cap для Intruder; якщо concurrency не задано, worker
  count тепер визначається розміром job list без верхньої межі;
- `limit=500` для Intruder polling; `since` працює, але результат не
  обрізається;
- `minInt(..., 100)` для WAF confidence display.

### `engine/routing.go`

Видалено ENV-backed dial timeout, keepalive, idle connection, TLS handshake,
response-header та expect-continue timeout defaults. `net/http.Transport`
тепер не отримує приховані верхні межі застосунку.

### `engine/burst.go`

Видалено:

- max URL/body/header/response/aggregate bytes;
- max iterations/concurrency/delay/timeout;
- global active-request і active-job semaphores;
- retention timer та автоматичне видалення старого burst з map;
- response/header truncation і `body_truncated`;
- обмеження `LimitReader` для JSON/action.

Робота приймає позитивні `iterations`/`concurrency` та невід'ємні
`delay`/`timeout` без верхньої межі. Якщо timeout дорівнює `0`, timeout не
встановлюється. Повні response headers і body зберігаються. Mode snapshot
змінено з `bounded_parallel` на `parallel`.

### `engine/last_byte.go`

Видалено:

- max URL/body/request/response/aggregate bytes;
- max header count/size;
- max iterations/concurrency/delay/hold/timeout;
- active-job/request семафори;
- retention cleanup;
- raw response, body і header truncation;
- обмеження `LimitReader` для JSON/action;
- default timeout/hold constants, які непомітно обмежували сирий job.

Перевірки CRLF, валідність HTTP method, абсолютний HTTP(S) URL, непорожнє
last-byte body та коректність порту лишилися як протокольні/синтаксичні вимоги.

### `engine/oast.go`

Видалено:

- max event count;
- max event string length;
- max nested list length;
- max provider body size;
- max poll interval і max timeout;
- max listener ID length;
- threshold `pollFailures >= 3`;
- 3-секундний delete timeout і 10-секундний provider timeout;
- provider response `LimitReader`.

`timeout_sec = 0` тепер означає listen без автоматичного deadline. Events
зберігаються повністю. Failure не завершує listener після третьої помилки;
помилка записується, а polling продовжується до callback, cancel або явного
timeout.

### `engine/osint_transforms.go`

Видалено:

- обмеження розміру response для transform, GitHub, Wayback та crt.sh;
- max subdomain results, DNS words, email profiles, S3 candidates;
- DNS worker-pool concurrency cap;
- 2-секундний timeout на DNS lookup;
- 5/8/10-секундні HTTP client timeouts;
- 30-секундний transform context timeout;
- 5 MiB GeoIP file cap;
- обмеження довжини domain/username/GitHub username;
- truncation GitHub commit events та subdomain result lists.

DNS brute-force тепер запускає кожен переданий candidate без верхньої межі
застосунку; результати сортуються, але не відкидаються за розміром.

### `engine/pkg/passive/passive.go`

Видалено:

- 64-байтний cap для capture context token;
- buffered subscriber channels на 32/16 events і silent event dropping;
- залежність від fixed-size channel як від явного queue limit.

`Store` тепер має per-subscriber чергу без обмеження: події не відкидаються
через повільного UI, а кожен subscriber має власну чергу. Це зберігає повну
SSE послідовність без silent truncation.

### `engine/pkg/scanner/nuclei_exec.go`

Видалено:

- upload file/total byte ceilings;
- Nuclei timeout/rate-limit fallback values;
- default `-rl` і `-timeout`, які додавалися при відсутності ENV;
- `bufio.Scanner` buffer cap `1 MiB`.

Nuclei JSONL читається через `bufio.Reader` без fixed line limit. Опційні
`-rl`, request timeout і process timeout додаються тільки при явному ENV.

Додано 2026-09-25 разом із per-file звітом:

- `stderr` більше не відкидається — діагностика бінарника потрапляє в
  `stats.stderr`, тому помилка запуску не зводиться до `exit status`;
- ненульовий exit код більше не скасовує вже зібраний звіт: `RunNucleiDir`
  повертає `NucleiRun` із per-file результатами й `stats.exit_status`, а
  помилку піднімає лише тоді, коли процес не стартував або контекст скасовано.

## 6. Що залишилося і чому

Це не приховані runtime limits:

- HTTP/HTTPS scheme, method token, CRLF та URL control-character validation;
- non-empty body для Last-Byte Sync;
- valid TCP port range `1..65535`;
- cron field syntax/ranges;
- marker syntax (`§name§`, `{{name}}`, `%name%`);
- JSON type validation та required fields;
- невід'ємні delay/timeout та позитивні iterations/concurrency;
- browser/Playwright та Go/Python/Django runtime semantics;
- database integer types та migration machinery;
- UI CSS layout bounds, zoom і viewport resize;
- UI polling/debounce/toast timers та browser settle waits — це scheduling, а не
  обмеження кількості або розміру даних;
- test-only timeouts у `*_test.go`, `tests` та browser-worker fixtures.

Користувач може сам задати `max_pages`, `max_depth`, `iterations`,
`concurrency`, timeout або delay. Це явні параметри, але вони більше не мають
прихованого верхнього обмеження з боку застосунку.

## Наслідки

Після видалення обмежень навмисно збільшуються ризики OOM, тривалих job,
великих JSON/response payload і нескінченних redirect/DNS polling scenarios.
Це очікувана поведінка запиту «без обмежень»; process-level memory, OS та
protocol constraints все одно залишаються чинними.
