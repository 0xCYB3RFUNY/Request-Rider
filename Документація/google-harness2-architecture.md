# Архітектура Google Research Harness² у платформі Request-Rider

## 1. Загальний огляд

**Google Research Harness²** (`google-research/harness2`, v0.1.0) — це фреймворк рекурсивного гартування агентних середовищ для роботи у відкритому світі (*Recursive Agent Harnessing for an Open World*). У платформі **Request-Rider** він інтегрований як постійний аналітично-валідаційний шар поверх `request-rider-mcp` та `request-rider-harness`.

Пакет фізично розміщений у `.agents/harness2/` та встановлений в editable-режимі (`-e ../.agents/harness2`) у віртуальне оточення MCP-сервера (`request-rider-mcp/.venv`).

## 3. Вісім компонентів оточення Harness²

Фреймворк декомпозує агентне середовище навколо моделі на **8 керованих компонентів**, які оптимізуються без зміни ваг самої LLM:

| № | Компонент | Роль у циклі виконання | Відповідник у Request-Rider |
|---|---|---|---|
| 1 | **`system_prompt`** | Формування базової поведінки та пріоритетів агента | Системні інструкції та контракт сесії |
| 2 | **`guardrails`** | Жорсткі обмеження безпеки, перевірка дозволених файлів та Scope | `check-scope`, заборона `shell=True`, redaction секретів |
| 3 | **`memory`** | Накопичення підтверджених знань та уроків між задачами | `Knowledge Hub` проєкту, журнали сесій та `improvement ledger` |
| 4 | **`tool_guidance`** | Правила вибору та безпечної параметризації інструментів | Описи схем та підказки `next_call` / `hint` у `request-rider-mcp` |
| 5 | **`subagents`** | Оркестрація вузькоспеціалізованих субагентів | Делегування розвідки, фаззінгу та верифікації знахідок |
| 6 | **`skills`** | Динамічне підвантаження спеціалізованих методологій | Каталог `.agents/skills/*` (553 скіли, індекс `.agents/skills.json`) |
| 7 | **`scripts`** | Детерміновані CLI-скрипти перевірки та автоматизації | `harness_runner.py`, `run_harness2.py` |
| 8 | **`plugins`** | Розширення та проміжні обробники (middleware) | Інтеграції MCP та плагіни середовища виконання |

## 4. Дворівнева рекурсія (Two-Level Recursion)

### 4.1. Рекурсія на рівні задачі (Task-Level Recursion: Propose–Probe–Compose)
Замість одноразового сліпого виконання задачі Harness² застосовує контрастивний цикл:
1. **Propose (Пропозиція)**: редактор харнесу пропонує інваріантні та доменно-специфічні покращення компонентів оточення для поточної задачі.
2. **Probe (Зондування)**: кандидати-харнеси паралельно (`--mode parallel`) або послідовно (`--mode sequential`) випробовуються на задачі з фіксацією трас виконання.
3. **Compose (Композиція)**: композитор порівнює поведінкові контрасти між прогонами (без потреби в ground-truth розмітці) і синтезує фінальний вдосконалений харнес.

### 4.2. Рекурсія на рівні гартування (Harnessing-Level Recursion)
Після завершення кожної задачі модуль **Experience Reflector** аналізує прийняті зміни та доказові спостереження, оновлюючи постійний реєстр покращень (*Improvement Harness / Ledger*), який використовується як стартова точка для наступних задач.

## 5. Інструменти MCP та CLI-інтерфейси

### 5.1. Інструменти у `request-rider-mcp` (Group 7)
У сервері `request-rider-mcp/server.py` зареєстровано три спеціалізовані інструменти:
- **`harness2_status()`**: повертає стан встановлення пакета `harness2`, версію (`0.1.0`), перелік 8 компонентів, підтримувані субстрати (`opencode`, `codex`) та опис трирівневої архітектури.
- **`harness2_run_demo(k=1, output_dir="")`**: запускає детермінований локальний цикл рекурсивного гартування (`harness2-demo`) із заданим бюджетом рекурсії `k` (1..5) без викликів зовнішніх платних API та повертає JSON-зведення `demo.json`.
- **`harness_pipeline_info()`**: повертає повну топологію трьох рівнів (`layer_1_core_mcp`, `layer_2_harnesses`, `layer_3_skills_arsenal`) із фактичною кількістю доступних скілів.

### 5.2. Виконувані утиліти у `request-rider-mcp/.venv/bin/`
- `harness2`: основний CLI для запуску бенчмарків та рекурсивного гартування (`--bench`, `--k`, `--mode parallel|sequential`, `--substrate oc|cx`).
- `harness2-demo`: локальний детермінований прогін рекурсії для перевірки цілісності пайплайну.
- `harness2-check`: перевірка готовності середовища та залежностей.
- `harness2-setup`, `harness2-judge`, `harness2-report`: встановлення бенчмарків, оцінювання та генерація звітів.

### 5.3. Скіл-раннер `.agents/skills/google-harness2/scripts/run_harness2.py`
Забезпечує вивід у форматі **Observation Contract** платформи Request-Rider:
```bash
python3 .agents/skills/google-harness2/scripts/run_harness2.py status
python3 .agents/skills/google-harness2/scripts/run_harness2.py demo --k 2
```
