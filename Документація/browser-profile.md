# Профіль браузера для обходу Target: як створити та імпортувати

## Що це таке

Поле **Browser profile** у вкладці Target дозволяє запустити browser-driven
обхід з каталогу профілю Firefox або Chromium. Профіль — це не просто папка з
налаштуваннями: у ній живуть **розширення**, ідентичність сесії, сертифікати,
cookies, а для Firefox — усі налаштування `about:config`.

Навіщо це потрібно саме тут:

| задача | без профілю | з профілем |
|---|---|---|
| вихід через VPN-розширення (Proton VPN тощо) | VPN не працює — браузер піднімається з чистим профілем, розширення не завантажене | працює, бо розширення є в профілі |
| власні cookies / авторизація на цілі | обхід щоразу без сесії | обхід приходить «своїм» відвідувачем |
| конкретні налаштування движка (WebRTC, DNS, шрифти) | неможливо задати через панель | беруться з профілю |
| обхід як у Chromium, а не Firefox | доводиться перемикати браузер у панелі | лишається Firefox, але з chromium-профілем (див. нижче) |

## Найпростіший шлях: скопіювати наявний профіль

### 1. Закрийте Firefox або Chrome

Профіль не можна копіювати, поки браузер його тримає. Якщо Firefox відкритий —
закрийте вікно (профіль звільниться), або створіть окремий профіль за кроком 2.

### 2a. Відділений профіль Firefox (чистий, без вашого основного)

```bash
firefox -P                      # діалог профілів: «Create Profile»
```

Дайте ім'я, наприклад `rr-crawl`, і **не** вмикайте синхронізацію. Далі
запустіть цей профіль, встановіть потрібні розширення, вийдіть із Firefox.

Каталог профілю покаже сам Firefox: `about:profiles` → **Root Directory** для
вашого профілю. Типовий шлях:

```
~/.mozilla/firefox/xxxxxxxx.default-release/
```

### 2b. Відділений профіль Chromium

```bash
google-chrome --user-data-dir="$HOME/chrome-profiles/rr-crawl"
```

Профіль створюється одразу. Типовий каталог:

```
~/chrome-profiles/rr-crawl/
```

### 3. Скопіюйте каталог у місце, яке не рухається

```bash
# Firefox
mkdir -p "$HOME/requestrider-profiles"
cp -a "$HOME/.mozilla/firefox/xxxxxxxx.default-release" \
      "$HOME/requestrider-profiles/firefox-rr"

# або Chromium
cp -a "$HOME/chrome-profiles/rr-crawl" \
      "$HOME/requestrider-profiles/chrome-rr"
```

Приберіть файли блокування, якщо вони залишилися:

```bash
rm -f "$HOME/requestrider-profiles/firefox-rr"/{lock,parent.lock,.parentlock}
```

`-a` (архівно) важливий: він зберігає права та часові позначки, без яких Firefox
відмовиться піднімати профіль.

### 4. Вкажіть шлях у панелі

У вкладці Target, у групі **Browser crawler**:

- **Browser profile** → `/home/<користувач>/requestrider-profiles/firefox-rr`
- натисніть **Start**

## Створення профілю з нуля (Chromium-профіль для Firefox)

Firefox приймає каталог, який відповідає його розкладці, тому профіль Chromium
можна використати з Firefox — але **навпаки ні**: розкладки різні, і профіль
Chromium у Firefox не відкриється.

Для сумісного профілю:

1. Створіть каталог, скопіювавши лише `Default` із профілю Chromium:

   ```bash
   cp -a "$HOME/chrome-profiles/rr-crawl/Default" \
         "$HOME/requestrider-profiles/chromium-rr/Default"
   cp -a "$HOME/chrome-profiles/rr-crawl/Local\ State" \
         "$HOME/requestrider-profiles/chromium-rr/Local\ State"
   ```

2. У панелі оберіть браузер **Chromium** і вкажіть цей каталог. Якщо
   залишити Firefox, профіль не підніметься — і обхід впаде з помилкою, а не
   піде тихо без профілю.

## Перевірка перед обходом

Найпростіше перевірити профіль тим самим способом, яким його користуватиметься
обхід:

```bash
cd browser-worker && PORT=8191 .venv/bin/python worker.py &
curl -s -X POST http://127.0.0.1:8191/headless/probe \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://check.torproject.org/api/ip","browser_profile":"/шлях/до/профілю"}'
```

У відповіді дивіться `body`: якщо там IP, відмінний від IP машини без
профілю — профіль піднімається і працює. Для VPN-профілю в тілі буде
`"IsTor": false` та адреса Proton, а не адреса Tor-виходу.

## Часті помилки

| симптом | причина | що робити |
|---|---|---|
| `browser_profile is not a directory: …` | шлях не існує або є файлом | перевірте шлях; поле не створює каталог |
| профіль піднімається, але VPN не працює | розширення не встановлене або вимагає входу | відкрийте профіль у браузері, авторизуйтесь, закрийте |
| `Firefox is already running` / профіль зайнятий | каталог відкритий у браузері | закрийте браузер або скопіюйте профіль у інше місце |
| обхід іде в стару сесію | Firefox відновив попередні вкладки з профілю | закрийте вкладки перед обходом: `browser.tabs.close()` у стартовому URL не допоможе, профіль відновлює їх сам |

## Правила, які варто знати

- **Один профіль — одна сесія.** Два паралельні обходи з одним профілем не
  отримають окремі сесії: другий побачить уже використані cookies. Для
  паралельних обходів потрібні окремі копії профілю або порожнє поле.
- **Профіль не копіюється автоматично.** Панель бере каталог як є. Це свідомо:
  мовча копіювати сотні мегабайт у тимчасову директорію — несподівана поведінка
  для інструмента, який ви вже відкрили.
- **Профіль — це ваші облікові дані.** Каталог містить cookies і збережені
  паролі. Не кладіть його в git, не робіть спільним для інших систем.
- **Поле не змінює те, як обхід виглядає без нього.** Порожнє поле = звичайний
  запуск браузера без профілю. Це додатковий спосіб виходу, а не режим.

## Пов'язане: список проксі

Поле **Proxy endpoints** у тій самій групі виконує іншу задачу — розподіляє
паралельні воркери обходу між різними вихідними адресами. Поля незалежні: можна
задати будь-яке, обидва або жодного.

- Порожнє поле → обхід без проксі.
- Один ендпоинт → те саме, що звичайне поле проксі.
- Два й більше → воркери розходяться між ними.

Ендпоинти приймаються через кому або з нового рядка. Постачальника проксі
система не створює: список задаєте ви.
